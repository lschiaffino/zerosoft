# AI policy for contributions

We build zerosoft with AI coding tools every day, and we welcome pull requests
written with their help. The rules are about responsibility, not about the
tool.

## The rules

1. **You understand the change.** You can explain every line you submit, why
   it is there, and what it affects. "The agent wrote it" is not an answer to
   a review question.
2. **You tested it.** You ran the checks in [CONTRIBUTING.md](CONTRIBUTING.md)
   and used the feature in the browser, like a person would. Tests that an AI
   wrote to pass its own code don't count as testing on their own.
3. **You disclose it.** Tick the AI box in the pull request template and say
   which tool you used and for what (for example "Claude Code wrote the
   migration and the tests; I wrote the UI"). Disclosure doesn't count against
   you.
4. **You own the license.** By signing the [CLA](CLA.md) you confirm you have
   the right to submit the code. Don't submit output that reproduces
   third-party code under an incompatible license, and don't paste code from
   sources whose terms you haven't checked.
5. **You keep it small.** Agents make large diffs cheap to write and expensive
   to review. Keep each pull request to one change, and remove generated noise
   (unrelated reformatting, unused helpers, comments that restate the code).

## What we close without review

- Pull requests that clearly weren't run or tested.
- Bulk, unsolicited changes across many files (mass refactors, style
  rewrites, "improvements" without an issue).
- Issues, reviews or comments generated by AI and posted without a person
  reading them first.

## For coding agents

If you point an agent at this repository, have it read [AGENTS.md](AGENTS.md)
first. It has the conventions, the checks and the definition of done.
